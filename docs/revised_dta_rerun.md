# Re-running revised holistic Jev on eight CLEF-TAR DTA reviews

The existing original **holistic** baseline is saved in data/jev_dta_scores.csv: 30,521 review-record pairs, 440 positives. Its mean WSS@95 is about 0.616 across all pairs, or **0.647978** on the 26,832 records with non-empty abstracts. These are **macro-averages over eight reviews**, not pooled record estimates.

## What differs

The baseline scores were produced by the older run_dta_benchmark.py: the review criteria and article text were concatenated into a single text state; the retain question was short.

The *current* run_dta_benchmark.py (updated in commit 829c439) places the review criteria and retain instructions inside the Noul question, with only the title and abstract in structured state. This is the **revised holistic** condition; it is not the five-question Jev-QA experiment. Reuse the existing script, but **never its original output directory**, which could intermingle runs.

A true paired prompt-organisation comparison also requires the same article texts, same review criteria, and same model version. The original released scores omit titles and abstracts, and no original source-text hashes are published. If the original PubMed cache is unavailable, a new fetch may introduce uncontrolled text changes. Matching PMID sets and abstract-availability flags does not prove byte-for-byte text identity. The comparison script rejects different returned model versions by default.

## Local Windows PowerShell procedure

From the repository root, use a clean working tree and, ideally, restore the PubMed metadata cache from your **original** scoring environment into data/pubmed_metadata_cache.json. The file is gitignored and must not be committed. The revised scoring output is similarly gitignored.

1. Install dependencies, with Python 3.10 or newer.

       python -m venv .venv
       .\.venv\Scripts\python.exe -m pip install -r requirements.txt

2. Validate the source, review/qrel alignment and PubMed retrieval without any Jev calls. The runner uses pinned CLEF-TAR and eligibility-criteria revisions. **Do not use --refresh-source** for this controlled comparison.

       .\.venv\Scripts\python.exe run_dta_benchmark.py --output-dir outputs/dta_revised --validate-only

   Stop if any PubMed retrieval failed. Check whether the saved PubMed cache really is the one used in the original September scoring run. The runner regenerates data/dta_source_manifest.json; inspect the working-tree diff and restore that manifest if it was replaced with a shorter autogenerated version.

3. Review the revised request in run_dta_benchmark.py, specifically request_state() and make_retain_question(). The eligibility criteria must be in Noul instructions, and the structured state must contain title and abstract only. Do not alter either prompt based on relevance labels or early results.

4. Only after validation and deliberate approval of the estimated paid Jev calls, set TYPESAFE_API_KEY locally. The full run creates up to **30,521 fresh Jev decisions** (including the missing-abstract records, so it matches the original all-record baseline) and can be resumed using its local SQLite checkpoints. Pricing and returned model version must be checked with the provider.

       $env:TYPESAFE_API_KEY = "your-local-key"
       .\.venv\Scripts\python.exe run_dta_benchmark.py --output-dir outputs/dta_revised --workers 8

   If the run is interrupted, rerun the same command, with the same output directory and unchanged criteria. Inspect outputs/dta_revised/dta_record_scores.csv for 30,521 complete rows with no errors. Do not copy original scores into the revised output; every retained revised probability must originate in the revised inference run.

5. Produce the strict paired comparison from the existing published baseline and the newly scored records.

       .\.venv\Scripts\python.exe analysis/compare_revised_dta.py

   If the ORIGINAL cache is no longer available, you can explicitly choose --skip-cache-check, but the report will state that input-text equivalence is unverified. If Jev returned another model version, the script stops; --allow-model-change permits a descriptive comparison but **not** an isolated prompt-organisation effect.

6. Review outputs under results/revised_comparison/:
   * paired_scores.csv: matching review/PMID scores, qrel labels and changes, without article text.
   * review_metrics.csv: WSS@95, WSS@100, MAP, recall and paired differences in both cohorts.
   * aggregate_metrics.csv: eight-review macro means and standard deviations, separately for all records and the non-missing abstract subset.
   * wss95_original_vs_revised_all.png and wss95_original_vs_revised_nonmissing.png.
   * README.md and comparison_metadata.json: reported figures and exact input checksums.

The comparator rejects incomplete/mismatched candidate sets, duplicated identifiers, label disagreements, non-finite probabilities, mismatched abstract counts, and unresolved revised scoring errors. It reproduces the saved filtered original mean WSS@95 before writing comparison outputs.

## Interpretation

These are retrospective rankings against *final review inclusion* labels, not necessarily original title/abstract screening decisions. WSS@95 is 1 - the fraction screened to reach at least 95% of filtered positives - 0.05. Calculate this per review before taking the unweighted mean. A post-hoc 95% recall cutoff is **not** a validated fixed-probability decision threshold.

Do not describe a result as a controlled request-organisation comparison if the model version or article inputs also changed. Published Akinseloyin results remain context, not a head-to-head experiment.
